# RLCD 统一界面与手动翻屏规格

日期：2026-10-06（UTC+8）

状态：产品方案与测试边界已确认；用户已授权开始开发。本文记录实施规格，实际验证结果另见项目说明与测试输出。

## Problem Statement

用户需要在 400 × 300 黑白 RLCD 上快速查看环境数据、Codex CLI 额度、账户余额和设备状态。当前各页面的 HEADER 不一致，时间与联网情况无法随时查看，独立 Footer 挤占正文空间；Codeck 页面自动翻屏，阅读位置无法由用户控制。

Codeck 首屏实际展示 Codex CLI 信息，但额度名称使用 PRIMARY / SECONDARY，终端图标也不能准确表达 OpenAI 品牌。余额账户各占一屏，阅读效率低。网络状态与系统信息分散，KEY 在任何页面长按都能触发配网。首页时间为 UTC+8，而 Codeck 时间直接展示接口中的 UTC 内容，容易误读。

## Solution

所有页面使用统一、固定的 HEADER，显示页名、HH:MM、Wi-Fi 连接与信号图标、电池图标及估算百分比。正文采用清晰的单色图标和卡片，不再设置固定 Footer。

顶层页面为“传感器 → Codeck → 网络/系统 → 传感器”。KEY 单击切换顶层页面；BOOT 单击按完整内容翻屏，到末屏后回到当前页面首屏。切换顶层页面时保留各页阅读位置，开机从传感器页开始。取消所有内容自动翻屏和滚动文字；自动更新数据和时钟仍正常进行。

传感器页首屏保留本机、客厅和书房温湿度；第二屏集中显示七项 Home Assistant Host Monitor 数据，通过 BOOT 手动翻看。UPTIME 时间换算为 UTC+8。

Codeck 首屏集中展示 OpenAI 图标、5H 与 7Day 剩余额度、UTC+8 重置时间，以及 CLI 状态、运行任务数、调度器开关、服务状态。余额每屏显示两个账户，卡片上下排列，各占整行。每张卡片展示品牌、账户名和全部币种余额；单币种使用大号金额，多币种分行并适当缩小字号。账户名最多两行，过长时省略，金额保持完整。

网络与系统信息合并为一个顶层页面，通过 BOOT 翻屏浏览。仅在该页面中允许 KEY 长按 3 秒进入 Wi-Fi 配网，并在网络卡片内保留操作提示。

## User Stories

1. As a device user, I want 每页都有相同的 HEADER, so that 我能用一致的位置读取设备状态。
2. As a device user, I want HEADER 显示当前页名, so that 我能判断正在查看哪类信息。
3. As a device user, I want 在每页看到 HH:MM 时间, so that 我无需返回传感器页查看时间。
4. As a device user, I want 所有时间都按 UTC+8 显示, so that 我无需自行换算接口时间。
5. As a device user, I want 校时前显示时间占位符, so that 未知时间不会被当成准确时间。
6. As a device user, I want 校时后断网仍继续显示走时, so that 临时断网不会使时钟消失。
7. As a device user, I want 用 Wi-Fi 图标区分联网与断网, so that 我能立即判断网络可用性。
8. As a device user, I want Wi-Fi 图标表达当前连接的信号强弱, so that 我能发现弱信号问题。
9. As a device user, I want HEADER 显示电池图标和估算百分比, so that 我能随时了解电量。
10. As a device user, I want 电量读数无效时显示占位符, so that 采样失败不会被误认为电量为零。
11. As a device user, I want 系统卡片明确电量属于估算, so that 我能正确理解数值精度。
12. As a device user, I want 保留本机、客厅和书房的温湿度卡片, so that 界面调整后仍能查看环境信息。
13. As a device user, I want KEY 单击循环切换三个顶层页面, so that 页面选择简单且可预期。
14. As a device user, I want BOOT 单击翻到当前页面下一屏, so that 我能自行决定阅读节奏。
15. As a device user, I want 翻屏时 HEADER 固定, so that 状态信息不会随正文移动。
16. As a device user, I want 在末屏再次按 BOOT 回到首屏, so that 我能持续循环浏览当前页面。
17. As a device user, I want 页面不会因等待时间变长而自行翻屏, so that 我有足够时间阅读。
18. As a device user, I want 返回顶层页面时保留先前的位置, so that 来回查看信息无需重新翻页。
19. As a device user, I want 开机从传感器页开始, so that 启动后有一致的入口。
20. As a device user, I want Codex 额度命名为 5H 和 7Day, so that 我能理解两个额度窗口的含义。
21. As a device user, I want 额度主数字表示剩余百分比, so that 我能快速判断还可以使用多少额度。
22. As a device user, I want 每个额度窗口显示重置日期与时间, so that 我能知道额度何时恢复。
23. As a device user, I want Codex 区域使用真正的 OpenAI 图标, so that 品牌表达准确。
24. As a device user, I want CLI、运行任务数、调度器和服务状态紧凑地出现在首屏, so that 我能快速查看整体情况。
25. As a device user, I want 调度器表示定时调度开关, so that 我不会将其误读为计时或倒计时功能。
26. As a device user, I want 状态图标同时带有短文字或数值, so that 黑白图标仍然容易理解。
27. As a device user, I want 余额每屏展示两个账户, so that 我能减少翻屏次数并保留较大字体。
28. As a device user, I want 两张余额卡片上下排列并占整行, so that 名称和金额有足够宽度。
29. As a device user, I want 在同一卡片内看到账户的全部币种, so that 我无需等待轮播或查找重复账户卡片。
30. As a device user, I want 每项金额都保留币种标识, so that 不同币种不会混淆。
31. As a device user, I want 单币种金额使用较大字体、多币种金额仍完整可读, so that 我能优先读出余额。
32. As a device user, I want 长账户名最多占两行并在超出时省略, so that 名称不会挤掉余额。
33. As a device user, I want 网络与系统信息在同一页面中通过卡片浏览, so that 我能集中检查设备状态。
34. As a device user, I want 看到网络连接、IP 和当前信号信息, so that 我能判断设备的网络状况。
35. As a device user, I want 继续看到芯片、核心数、Flash、PSRAM、显示参数、SDK 版本及电池详情, so that 原有系统信息不会遗漏。
36. As a device user, I want 仅在网络/系统页长按 KEY 3 秒进入配网, so that 在其他页面长按不会误触配网。
37. As a device user, I want 长按 KEY 松开后不再产生单击切页, so that 一次操作不会同时执行两个动作。
38. As a device user, I want 网络卡片保留配网操作提示, so that 去掉 Footer 后仍能找到设置入口。
39. As a device user, I want 去掉固定 Footer, so that 正文有更多空间展示卡片。
40. As a device user, I want 数据缺失时看到占位符而非假定的零值, so that 我能区分未知与真实数据。
41. As a device user, I want 旧余额与失败后保留的快照仍明确标注, so that 紧凑布局不会掩盖数据新鲜度。
42. As a device user, I want 请求失败时仍看到最后成功数据和具体错误, so that 临时故障不会使所有已知信息丢失。
43. As a device user, I want 数据刷新不改变我正在阅读的有效屏幕位置, so that 查看信息时不会被打断。
44. As a device user, I want 首次配网、重连和后台采样继续正常工作, so that 界面改进不影响已有功能。
45. As a device user, I want 在传感器页浏览 Host Monitor 的七项主机实体, so that 我能查看服务器负载、运行时间和网络速率。
46. As a device user, I want 主机数值带有 Home Assistant 返回的测量单位, so that 速率和温度读数含义明确。

## Implementation Decisions

- **显示与布局**：沿用 400 × 300、1-bit 单色 framebuffer 和现有绘图原语；以清晰边界、留白、图标和短标签组织卡片。所有页面及配网视图共用 HEADER；HEADER 至少包含页名、HH:MM、Wi-Fi 状态/信号、电池图标和百分比。正文翻屏不移动 HEADER。移除固定 Footer，其原有必要状态移入对应卡片。
- **页面职责**：保留传感器页面及原有三张温湿度卡片；新增一屏 Host Monitor CPU、内存、磁盘、温度、运行时间和网络速率；保留 Codeck 页面；将独立网络、系统页面合并为网络/系统页面。配网继续作为既有独立视图，保留其热点与网页操作说明。
- **导航状态**：UI 控制模块维护顶层页面与各页当前内容屏。KEY 单击只切顶层页面；BOOT 单击只翻当前页面内容；末屏回首屏。每页位置在本次运行中保留，不新增 NVS 持久化；重启回到传感器页，各页内容位置初始化为首屏。
- **手动翻屏**：删除按经过时间推进 Codeck 内容屏的逻辑，不引入平滑滚动、自动内容轮播或滚动文字。数据与时钟自动刷新照常运行。收到新快照时保留仍有效的内容屏位置；若内容屏数量减少导致位置无效，收敛到最后有效屏，避免越界。更新数据不得伪装成 BOOT 翻屏事件。
- **按键输入**：扩展现有按键模块以区分 KEY 与 BOOT，复用消抖和短按/长按识别。保留 KEY 3 秒长按阈值、约 40 ms 消抖和约 20 ms 轮询。长按释放不再产生短按。仅网络/系统页面接受 KEY 长按配网请求，其所有内容屏均适用；其他普通页面的 KEY 长按无动作，且不触发松开切页。
- **BOOT 硬件核实**：当前工程没有 BOOT 的引脚定义和处理逻辑；实施时必须根据实际板卡资料或出厂代码确认引脚、有效电平及启动用途，不凭惯例猜测 GPIO。正常运行时增加单击翻屏，不改变开机下载模式用途，不新增 BOOT 长按动作。
- **配网生命周期**：仅限制手动长按入口；首次没有有效配置时自动进入配网、后台网络线程管理门户、保存配置、自动重连、配网成功恢复页面等现有机制继续工作。配网页继续现有浏览与退出行为，不因取消 Footer 删除热点和配网地址等必要信息。
- **网络快照**：现有 Wi-Fi 状态快照尚无已连接 SSID 和实时 RSSI。由网络模块补充线程安全的当前连接信息，供 HEADER 信号图标与网络卡片使用；不将扫描列表的 RSSI 当成当前连接信号。断网、连接中和信号未知应有可区分的表示，不复用陈旧强信号图标。信号等级阈值在实施中集中定义并验证。
- **HEADER 刷新**：网络状态、信号、电池、时间变化应在所有页面生效，不能继续仅在传感器页因时钟变化而重绘。主任务仍为唯一 framebuffer 所有者；后台网络任务不得直接绘图。按键不等待网络请求或 SNTP。
- **电量语义**：沿用电压推测的电池检测和估算百分比，不把它描述为硬件电量计或可靠的物理插入检测。HEADER 有效时显示图标和百分比；未知或不能可靠显示百分比时使用占位符，不伪造 0%。网络/系统页保留电压、推测检测状态及估算说明。
- **时间职责**：时间服务继续使用 UTC+8，HEADER 显示 HH:MM；系统卡片可展示日期与时区。首次 SNTP 成功前使用占位符，已校时后断网继续走时。Codeck 的快照生成时间、额度观测时间、账户观测时间和重置时间均正确解析为时间点后转为 UTC+8，不能通过截取 UTC 字符串或只给小时加 8 实现转换。覆盖日期、月份、年份与闰日进位；无效或缺失时间显示占位符。界面不再把显示时间标为 UTC。
- **Codex 额度**：API 的 primary / secondary 字段契约保持原义，展示名称分别为 5H、7Day。有效额度主数字及进度条表达剩余比例，即 100% 减已用比例；未提供或不可用时显示占位符。各窗口显示 UTC+8 的重置日期和时间。无需新增独立的已用主数字。
- **Codex 状态**：首屏紧凑显示 CLI 可用性、运行任务数、调度器开关、服务可用性；图标配短标签或数值。调度器表示已有 scheduler_enabled，不新增运行时长、倒计时或定时任务管理。运行状态仍是任务数量，不假设存在任务明细。
- **品牌资源**：将 Codex 区域的终端 UI 图标替换为官方 OpenAI 品牌图形，保留来源记录并按比例生成单色资源。沿用既有品牌图标生成与绘制机制，不用手工近似终端标识冒充 OpenAI 图形。DeepSeek 与 OpenRouter 继续使用已有品牌资源。
- **余额分页**：首屏之后按接口顺序每屏最多两个账户，各账户只出现一次，上下排列、占整行。账户内全部币种在同一卡片分行展示，不按币种再分页、不自动切换金额，不合计或换算币种。奇数个账户的末屏只显示最后一个账户；空余额保持明确空数据说明，不生成演示数据。
- **余额排版**：单币种金额优先使用大字号；多币种最多四项，使用足以完整容纳金额与币种的分行布局。名称最多两行，按实际像素宽度换行并在超出时省略；UTF-8 字符不从中间切断。模型保留名称原文；原有中文字体及未知字符回退机制继续适用。
- **金额准确性与极端长度**：沿用十进制字符串和已有精确格式化规则，不通过浮点数覆盖原值。支持契约范围内的长金额；不能用省略或裁切隐藏金额高位、负号或币种。必要时降低字号或继续换行，并通过极端长度样例确认仍在同一卡片内完整可读。
- **网络/系统卡片**：集中展示网络连接状态、当前连接信息、IPv4、门户状态及配网入口提示；系统卡片保留芯片、核心数、Flash、PSRAM、分辨率、SDK 版本和电池详情。新增第三个内容屏，以进度条显示运行应用镜像相对应用分区的占用、内部 heap 和 PSRAM heap 的当前占用，并列出低水位与最大连续块；内存数值每 30 秒采样。按完整卡片组织内容屏，不拆断一张卡片的阅读。
- **错误与新鲜度**：保留缺失数据显示占位符、单账户旧数据标记、失败后最后快照标记及具体错误。继续区分单个账户陈旧与整份快照缓存。快照、额度、账户各自的时间语义不得合并成同一个“更新时间”；Footer 移除后这些信息在对应内容区域中保留。
- **数据契约**：本次不更改 Codeck 只读快照 API、轮询/认证/TLS/退避策略、严格解析规则或现有八账户、每账户四币种等模型上限；只调整呈现与本地导航，并增加必要的网络显示快照字段。

## Testing Decisions

### 已确认的测试边界

主测试边界选择 **“生产 UI 输入 → 页面状态 → 实际绘图输出”**。优先扩展项目已有的生产 C 绘图预览入口；在该入口上增加可控的时间、按键和设备快照输入，覆盖统一 HEADER、导航以及网络/系统页。目标是以一个较高层的 UI 行为入口验证交互和视觉结果，避免为每个卡片内部函数另设测试接口。

既有 Codeck 解析器与模拟传输回归继续作为数据契约保护，不为本次排版修改另起同类测试体系。硬件电气状态、真实 BOOT 手感、ADC 与当前连接 RSSI 另做上板验收；主机模拟不作为这些硬件事实已经验证的证据。

### 好测试的标准与先例

- 只断言用户可观察的行为：当前页面、当前内容屏、显示文字与数据、是否发起配网请求、画面是否完整可读；不锁定私有函数调用次数或内部字段组织。
- 复用现有生产解析器和生产绘图代码生成 400 × 300 预览；延续已有字形、边界、文字重叠与图形遮挡检查，并逐屏人工检查最终 PNG。不要用独立的演示排版代替真实页面。
- 复用现有解析与模拟 HTTP 传输测试保护金额精度、部分数据不可用、认证/网络错误和最后成功快照保留等外部行为。
- 若旧预览入口只能绘制单个 Codeck 内容屏，则向上扩展到 UI 控制与公共绘图入口；以依赖输入替身模拟按键、时钟和快照，不引入仅为测试存在的产品操作。

### 自动化与视觉验收覆盖

1. KEY 单击循环传感器、Codeck、网络/系统三个页面；BOOT 单击不改变顶层页面。
2. 进入 Codeck 初始为额度首屏，随后每个余额屏最多两个账户；两张卡片上下排列。
3. BOOT 每次推进一个完整内容屏，末屏回首屏；传感器页在温湿度首屏和主机监控屏间循环。
4. 离开 Codeck 或网络/系统页再返回时保留各自位置；重启初始化为传感器页和各页首屏。
5. 推进模拟时间超过旧的 12 秒轮播周期，内容屏仍不自行切换；时钟、数据刷新不停止。
6. 新快照页数不变时保持位置；页数减少时位置仍有效，不越界、不读取不存在账户。
7. KEY 达到 3 秒阈值时只在网络/系统页发起一次配网请求；松开不追加短按；其他普通页无配网请求和切页副作用。
8. 双按键消抖覆盖短抖动、连续单击和长按释放；BOOT 长按不被当成连续翻屏功能。
9. 传感器、Codeck、网络/系统与配网视图的 HEADER 一致且固定，无固定 Footer。
10. HEADER 在任意页面响应分钟变化、Wi-Fi 连接变化、信号等级变化与电池读数变化；时间未知和电量未知显示占位符。
11. Wi-Fi 已连接、连接中、断开、信号弱和信号未知均有明确表示；网络断开不会保留虚假的强信号图标。
